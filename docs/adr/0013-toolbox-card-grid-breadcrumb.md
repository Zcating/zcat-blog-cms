# 工具箱移除侧栏导航，改为卡片网格 + 两级面包屑

工具箱此前有两份互不相干的清单：侧栏（`apps/blog/app/features/toolbox/pages/toolbox-layout.tsx`）与首页（`apps/blog/app/features/toolbox/pages/toolbox-home.tsx`）各维护一份工具入口。侧栏列了 7 个工具入口，外加「导航」「常用」两个分组标签；首页只有 6 张卡片；而工具实际有 9 个。两份清单互相漏项：首页缺 Hash 计算、AES 加解密、二维码生成，侧栏缺 Markdown 转 HTML、JSON 查看器。没有哪一处列全，也没有任何机制要求它们一致。

侧栏本身也无法指示位置：它没有传入当前值，高亮从未生效。它在窄屏上还要靠顶部按钮唤出抽屉才可见。于是「我在哪」与「怎么回总览」两件事都没有被真正承担。

## 决策

- **移除工具箱专属侧栏。** `/toolbox` 不再渲染自己的侧栏，改为满屏外壳：顶部全站主导航 → 内容区 → 全宽页脚。
- **工具箱首页展示全部 9 个工具卡片。** 一个不少，按使用场景排序：Markdown 转 HTML、JSON 查看器、IP 查询、Hash 计算、AES 加解密、RSA 加解密、图片和 Base64 互转、二维码生成、身份证生成。
- **工具子页面用两级面包屑定位**：「工具箱 / <工具名>」。第一级链回工具箱总览，末级是当前位置（工具名），不是链接。工具箱总览页不显示面包屑。
- **工具清单只有一个来源。** 工具条目以 `ToolEntry` 表达，全部条目由唯一的工具注册表 `TOOL_REGISTRY` 持有；首页卡片与工具子页面的面包屑都从它派生。清单只有一份，就不需要第二份需要同步。

## 理由

**为什么是面包屑而不是侧栏。** 侧栏在窄屏上要靠顶部按钮唤出抽屉才可见，移动端默认不在视野里；它自身也没有生效的高亮——没有传当前值——所以即便在宽屏上展开，它也不能指示「我在哪」。面包屑同时承担两件事：末级报告当前位置，首级给出回总览的路径。侧栏两件事都只做了一半。

**为什么清单要单一来源，而不是把两份清单都补全。** 补全只解决当下这一次漂移。清单在侧栏与首页各维护一份时，新增或移除一个工具要改多处，漏改一处就静默少一个入口，而这种缺失没有任何测试能捕获——两份清单各自的测试都是绿的。清单只有一份之后，首页少一张卡片或工具页少一级面包屑，都会直接暴露为注册表里少了条目。

## 后果

- 侧栏配置（「导航」「常用」两个分组标签与 7 个工具入口）随侧栏一并删除。工具箱改用顶部全站主导航 `LayoutHeader` 与全宽页脚 `LayoutFooter`。
- 工具箱首页现有的 6 张卡片改为从注册表派生，渲染全部 9 个工具。
- 工具清单从两处收敛为一处：`ToolEntry` 与 `TOOL_REGISTRY` 是**运行期**唯一的清单表达，首页卡片与工具子页面的面包屑都从它派生，页面不再各自持有清单。注册表的单元测试里刻意留了一份清单作为**变更闸门**——增删工具必须同时改它，漏改则测试失败。这与从前不同：从前的两份清单各有各的绿测，漏改静默通过；现在漏改会响。
- 面包屑的末级文本取注册表里的 `name`，与工具页自身的 `h1` 不一定一致（已知三处不一致），这是预期差异，不改工具页。
- 依赖旧侧栏结构的断言需要改写：`apps/blog/e2e/toolbox-ssr.spec.ts` 断言 SSR HTML 含 `data-slot="sidebar-wrapper"`，侧栏一删即失效。仓库根 `pnpm test` 只跑 vitest、不跑 Playwright，抓不到这类断裂。
