# 博客首页改为混合瀑布流，新增公开照片流接口

博客首页此前是「左侧栏（头像 / 排序 / 日历）+ 文章列表 + 分页」的二栏结构。**已决**：改为顶部工具行 + 单一 `ZWaterfall` 混合网格，网格内混排照片卡、文章文字卡与一张头像介绍卡；移除分页，固定展示最新文章与照片，剩余内容通过工具行的「全部文章 / 全部相册」链接进入既有页面。为此新增公开接口 `GET /api/blog/photo/list`。

## 为什么需要新接口

既有 `/api/blog/gallery` 返回的是**相册**列表，每个相册只有一个封面照片——它无法铺开散落的照片。要在首页铺照片，就必须有一个按时间排序、跨相册返回**照片本身**的查询。复用 `/api/blog/gallery` 会把「相册」误当作「照片」，得到的是相册封面墙，不是照片墙。

新接口遵循既有的分页结果契约（ADR-0006），与 `/api/blog/article/list` 对称，而非为首页定一个专用的一次性端点——首页只取第一页，但接口本身是通用列表。

## 照片流只含已发布相册内的照片

照片必须归属 `available = true` 的相册才进入照片流。未归入相册的零散照片没有归属，点击后无处可去，与 `/api/blog/gallery` 的 `available` 过滤保持一致。

实现上因此分两步：先查 `available` 相册的 `id` 与 `name`，再用 `albumId: { in: [...] }` 过滤照片。**不能**用 Prisma 的关系过滤 `{ album: { available: true } }`——`Photo` 与 `PhotoAlbum` 之间没有声明关系字段，`Photo` 上只有裸的 `albumId Int?`，关系过滤在类型层就不成立。相册名由前一次查询的 `Map` 回填。

## 排序下拉只作用于文章

工具行的排序下拉控制**文章**的取哪几条与顺序；照片流固定按发布时间倒序，不受下拉影响。二者语义不同：一个是「你想先看什么」，一个是「最近拍了什么」。

## ZChat 组件保留

删除 AI 聊天时只删 `apps/blog` 侧的接入实现与 `idb` 依赖，`packages/ui` 的 `ZChat` 与 `packages/doc` 的对应文档**保留**。`ZChat` 是通用聊天 UI 组件而非 AI 专用实现，且 blog 的项目规范要求非必要不改动 `packages/ui`。后端自始没有 AI 聊天代码——它纯由浏览器直连模型服务商。
